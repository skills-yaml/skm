# Blocked Specs

Work blocked or deliberately deferred from backlog, development, or test.
Use `blocked/<primary-feature>/<spec>.md` and a matching root catalog row.

Every blocked spec records `State: blocked`, `Previous State` (backlog,
development, or test), `Block Kind` (impediment or deferred), `Block Reason`,
and `Resume Condition`. Reasons and conditions must be nonempty.
Resume at the recorded previous stage and renew stale review, verification,
and acceptance evidence. Synchronize catalog and release member paths.
Blocked development/test work retains its version and memory obligations.
